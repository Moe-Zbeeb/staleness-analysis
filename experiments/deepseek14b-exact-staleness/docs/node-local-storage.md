# Node-local working storage

The 3B storage migration keeps the frozen Qwen2.5-3B model, dataset membership, grader, GRPO loss, 512-response batches, seven-GPU topology, 1,000-update budget and delayed-rollout lag 256 unchanged. Full recovery checkpoints remain every 100 updates, with the existing retention policy. This does not adopt the separate historical-policy-checkpoint algorithm or the teammate's three-runs-per-node/evaluation layout.

`scripts/node_local_run.py` stages the existing Linux CPython distribution, virtual environment, pinned official PrimeRL checkout and its editable dependencies onto local disk. Environment staging uses at most eight independent package transfers and excludes unused package test directories and bytecode caches. It rewrites only runtime path metadata and executable entry-point paths; it does not change the imported PrimeRL library source. The scientific source is copied from the immutable launch release and checked against its package manifest. Model files are checked against the original pinned manifest; dataset, prepared question manifest and tokenizer hashes are preserved. Runtime import paths and Python's base prefix are checked for local storage.

Active output, rollout archives, exact-age cohort queues, recovery checkpoints, TensorBoard event files, temporary files and compilation caches live under `/tmp/staleness-storage-v2/mohamadzbib/<run>`. The runtime lives under `/tmp/staleness-runtime/mohamadzbib/<runtime>`. These locations are verified as local disk, not inferred from their names. CUDA, vLLM, TorchInductor, Triton, Hugging Face, UV and temporary caches are isolated per run. OMP, MKL and OpenBLAS threads are each limited to one. This run exclusively owns its node's CPU allocation.

The training configuration sets `metrics_mirror_root` to null so its normal observers never contact shared storage. A separate standard-library backup process copies the complete run to its unique NFS output directory and metrics/TensorBoard data to its unique XFS directory. TensorBoard is the only live tracking backend. No Runboard process or intermediate evaluator starts.

`scripts/local_backup.py` copies one transfer at a time under a local lock. It flushes each temporary destination, hashes the copied bytes and rereads the destination to verify its checksum before atomic publication. Only recovery checkpoints with the controller's complete marker are eligible. Every trainer shard, optimizer state, sampler/RNG component and delayed-cohort queue is copied and hashed. Checkpoint directories stay hidden while incomplete and are atomically published with `backup-verified.json` only after verification. Existing unrelated destinations are rejected by run UUID and configuration/source identity. Existing checkpoints are retained; no new deletion policy is introduced.

Shared-storage failures produce a local backup status and retry in the backup process. They do not make the learner perform network I/O. The supervisor stops if the backup process exits, reserves 50 GiB of free local disk, and checks inference readiness with a separate 30-minute startup deadline. Generation and learner deadlines remain those of the frozen study. On normal shutdown it requests a final backup and waits up to one hour. Local files are retained if copying fails. Slurm's termination grace can be shorter, so a preemption or node loss may leave only the last verified shared checkpoint recoverable.

Local disk is temporary. A local checkpoint is not a durable shared recovery point until `backup-verified.json` exists in the published shared directory. On recovery, verify the backup manifest and original run identities, restore to compatible local asset paths, and explicitly resume from that complete checkpoint. Never treat Slurm requeue as checkpoint recovery or silently restart over existing outputs. The launcher deliberately refuses automatic requeue and output reuse.

The teammate's source links point to another Mac and were not accessible in this workspace. This implementation follows the supplied storage design and is adapted to this repository's delayed-rollout protocol; it is not a copy or verified audit of those two files.
