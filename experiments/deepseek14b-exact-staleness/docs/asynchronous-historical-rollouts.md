## Policy clock and work assignment

`theta_v` denotes the policy after `v` optimizer updates. Updates 1–256 use on-policy cohorts from `theta_0` through `theta_255`. Independently, immutable exports of these versions are given to the historical worker, which generates distinct cohorts for their eventual consumption steps. Export publication runs in the background; the main learner does not wait for those rollouts during bootstrap.

Update 257 trains `theta_256` using the cohort generated by `theta_0`; update 258 trains `theta_257` using `theta_1`. Every later consumed cohort must have age exactly 256. Wall-clock generation time is irrelevant: the complete response must come from its designated frozen policy, and its original behavior log-probabilities and rewards are retained. The learner waits if the required cohort is missing; it never substitutes a fresher cohort.

After bootstrap, the learner's local inference pool generates future cohorts concurrently with training on older data. It finishes its complete cohort before inference weights advance. Remote workers finish their bootstrap assignments and release their allocation. Exports stop after policy version 743 because later versions would produce data beyond the 1,000-update budget. The final 256 updates drain the existing queue; they need no new generation.

## Deployment and communication

The prepared topology uses one complete nine-A100-40GB high-priority node: four trainer GPUs and five current-policy inference GPUs. A second high-priority allocation supplies three inference GPUs for bootstrap historical work. This respects the twelve-A100 high-priority quota. Every trainer rank stays on one node. Separate inference pools do not participate in a shared NCCL group.

Each inference GPU runs an independent official PrimeRL TP1/DP1 server. A local `vllm-router` 0.2.0 process distributes requests round-robin across that node's replicas; its retry policy permits exactly one attempt per request. Administrative weight updates target every replica directly. GPU assignments, per-replica seeds, isolated compilation caches and readiness are recorded. Worker processes are supervised as owned process groups, with bounded startup and shutdown. No inference request crosses between the learner node and the historical-worker node.

The local learner and its inference pool use PrimeRL's filesystem weight transport. Current weights, assets, Python runtime, compilation caches, rollout archives and active recovery checkpoints stay on node-local storage. Remote historical work uses checksum-verified immutable weight exports staged locally before loading. Only those remote exports and completed result files cross shared storage. Full recovery backups run in a separate process and are checksum-verified before publication.

This removes cross-node collectives and the old forced Socket-only communication settings. It does not prove a speedup: local FSDP communication, generation, verification, checkpoint serialization and remote export latency are still measured separately. The first complete updates are needed before estimating throughput.

## Correctness and failure behavior

`AsyncQueueState` records both completed cohorts and outstanding export jobs. Each export binds the model version, consumption step, dataset/manifest hashes, source identity, run identity and weight hashes. Each result binds the same job and carries a verified archive hash. The learner validates response/question mappings, token streams, finite log-probabilities and advantages, sampling settings and exact policy provenance before accepting it.

Recovery checkpoints include the exact delayed queue and immutable exports for unfinished historical jobs. Their completion marker is written only after these components are sealed. Existing complete results can be recovered after their redundant shared weights have been removed. A failed or abandoned generation attempt does not silently resample. Failure, preemption or disk exhaustion stops the affected allocation and requires an explicit compatible recovery launch; automatic Slurm requeue and implicit restarts from initial weights are disabled.

## Library integration

Official PrimeRL remains pinned at `ab5de8fff44b2c4a5c85e24b6e6e3f7d57eee7b1`, as enforced by `verify_upstream`.

No imported PrimeRL or vLLM source is edited. The new adapters are `rollouts/async_queue.py`, `rollouts/historical.py`, `rollouts/history_store.py`, `runtime/historical_worker.py` and `runtime/inference_pool.py`. Historical workers temporarily replace the orchestrator's weight-receiver factory in their own process so they can load explicitly assigned frozen exports without joining a live learner receiver. The factory is restored immediately after setup, including on failure. Existing trainer checkpoint and diagnostic-token adapters remain in use. These interfaces are version-sensitive and require revalidation before any upstream upgrade.

The repository's default model remains 14B. This deployment's frozen release selects the verified 1.5B model manifest and matching constants before its package hashes are sealed. Source identity and model revision are captured from the deployed release, rather than inferred from the repository default.
