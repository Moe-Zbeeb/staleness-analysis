## Exact-age schedule

`theta_t` is the model after `t` completed optimizer updates. Bootstrap updates use separate fresh on-policy cohorts and build a queue of future cohorts. Each queued cohort retains the original responses and behavior log probabilities from one frozen policy version.

| Update number | Learner before update | Behavior policy of consumed cohort | Age |
| --- | --- | --- | --- |
| 1 | `theta_0` | `theta_0`, bootstrap | 0 |
| 256 | `theta_255` | `theta_255`, bootstrap | 0 |
| 257 | `theta_256` | `theta_0`, deferred | 256 |
| 258 | `theta_257` | `theta_1`, deferred | 256 |
| 1,000 | `theta_999` | `theta_743`, deferred | 256 |

The queue reaches 256 cohorts, or 131,072 responses. At the response cap this represents up to 1,073,741,824 response tokens, plus prompt tokens, log probabilities and other payload fields. This is queue capacity, not a measured RAM requirement. Full-length queue memory and checkpoint I/O remain unverified. The current controller holds serialized pending payloads in CPU memory and serializes the queue again at recovery checkpoints.

Generation stops after the deferred cohort from `theta_743`. The last 256 updates drain the queue, leaving no unused rollouts. Across the full schedule, 1,000 distinct cohorts are generated and consumed once. The controller rejects a consumed cohort with the wrong age.

Checkpoints 100 and 200 contain only bootstrap training. Checkpoint 300 contains 256 bootstrap updates and 44 exact-256 updates. Checkpoint 1,000 contains 256 bootstrap updates and 744 exact-256 updates. LR warm-up remains 30 updates and is independent of the 256-update queue bootstrap.
